# Robust and Efficient Prompt-Based Federated Continual Learning

This repository contains the implementation and experiments for a thesis study on **rehearsal-free prompt-based Federated Continual Learning (FCL)** using a frozen Vision Transformer (ViT) backbone.

The code is based on the **Fed-CPrompt** framework and contains experiments on:

- CIFAR-100 continual learning
- MedMNIST balanced / CIFAR-style continual learning
- MedMNIST cross-domain continual learning
- IID and non-IID federated client distributions
- Trainable federated classifier behaviour and forgetting
- Bounded prompt-pool extensions using eviction, merging, and hybrid policies

---

## Repository Contents

```text
.
├── akarshprompt_boundedcode.py
├── akarshboundedmedical.py
├── akarshmedicalsamedomain.py
└── README.md
```

### `akarshprompt_boundedcode.py`

CIFAR-100 implementation of the prompt-based federated continual-learning pipeline. It uses a frozen ViT-B/16, trainable prompts, a trainable classifier, C2Loss, and FedAvg. It also contains the bounded prompt-storage extension.

### `akarshboundedmedical.py`

MedMNIST **cross-domain** experiment. Each continual-learning task corresponds to a different medical imaging modality.

Default tasks:

```text
Task 1 -> PathMNIST
Task 2 -> DermaMNIST
Task 3 -> BloodMNIST
Task 4 -> OCTMNIST
Task 5 -> OrganAMNIST
Task 6 -> RetinaMNIST
```

The implementation uses the first four classes from each modality, giving 24 classes across 6 tasks.

### `akarshmedicalsamedomain.py`

MedMNIST **balanced / CIFAR-style** experiment. Classes from multiple MedMNIST datasets are pooled, shuffled, and divided into balanced continual-learning tasks.

# 20. Bounded Prompt-Pool Experiments

`akarshprompt_boundedcode.py` contains the bounded prompt-storage extension.

When the prompt pool reaches the configured capacity and a new task arrives, the implementation can use one of three policies:

```text
evict  -> random eviction
merge  -> merge the two most similar prompts
hybrid -> merge when sufficiently similar; otherwise utility-based eviction
```

The main environment variables are:

```text
AK_POOL_CAP
AK_POOL_POLICY
AK_MERGE_THRESH
AK_UTIL
```

---

# 21. Unbounded Prompt Pool Baseline

Run the normal baseline with no prompt-pool capacity:

```bash
unset AK_POOL_CAP
unset AK_POOL_POLICY
python akarshprompt_boundedcode.py
```

The default `AK_POOL_CAP` is unset, which means the prompt pool is unbounded.

---

# 22. Bounded Pool with Random Eviction

Use a prompt-pool capacity of 2 and random eviction:

```bash
AK_POOL_CAP=2 \
AK_POOL_POLICY=evict \
AK_CLIENTS=10 \
python akarshprompt_boundedcode.py
```

When the pool is full and a new task arrives, a prompt slot is freed by random eviction.

---

# 23. Bounded Pool with Prompt Merging

Use a capacity of 2 and prompt merging:

```bash
AK_POOL_CAP=2 \
AK_POOL_POLICY=merge \
AK_CLIENTS=10 \
python akarshprompt_boundedcode.py
```

The merge policy combines the two most key-similar prompts to free a slot for the new task.

---

# 24. Bounded Pool with Hybrid Policy

Use the hybrid policy:

```bash
AK_POOL_CAP=2 \
AK_POOL_POLICY=hybrid \
AK_CLIENTS=10 \
python akarshprompt_boundedcode.py
```

The hybrid policy first checks prompt similarity. If the closest prompt pair satisfies the merge threshold, it merges them. Otherwise, it evicts the prompt with the lowest utility.

The default merge threshold is:

```text
0.3
```

To change it:

```bash
AK_POOL_CAP=2 \
AK_POOL_POLICY=hybrid \
AK_MERGE_THRESH=0.5 \
AK_CLIENTS=10 \
python akarshprompt_boundedcode.py
```

---

# 25. Utility-Based Eviction Option

The bounded implementation supports the utility-clean mode:

```bash
AK_POOL_CAP=2 \
AK_POOL_POLICY=hybrid \
AK_UTIL=clean \
AK_CLIENTS=10 \
python akarshprompt_boundedcode.py
```

# 32. DataLoader Workers

The medical scripts expose an optional worker setting through `AK_WORKERS`.

Default:

```text
AK_WORKERS=0
```

This is conservative and avoids shared-memory related DataLoader issues.

To use workers:

```bash
AK_WORKERS=2 \
python akarshboundedmedical.py
```

You can also set the prefetch factor when workers are enabled:

```bash
AK_WORKERS=2 \
AK_PREFETCH=4 \
python akarshboundedmedical.py
```

If you encounter `/dev/shm` or DataLoader worker problems, use:

```bash
AK_WORKERS=0
```

# 33. Output Files

During training, the scripts periodically save checkpoints.

Checkpoint files use the form:

```text
akarsh_ckpt_<run_tag>.pt
```

At the end of training, a history CSV is saved:

```text
<run_tag>_history.csv
```

The CSV contains:

```text
Task
Average Accuracy
Forgetting
```

For bounded-pool experiments, the final console output also reports:

```text
Number of merges
Number of evictions
Active prompt slots
Prompt masses
```

---

# 34. Resume an Interrupted Run

The scripts automatically look for a checkpoint corresponding to the current `run_tag`.

If a matching checkpoint exists, the run can resume from the saved state.

For example:

```bash
python akarshboundedmedical.py
```

If the same configuration was previously interrupted and its checkpoint is still present, the script can load the checkpoint and resume.

---

# 35. Start a Completely Fresh Run

If you want to restart an experiment from the beginning, remove its checkpoint and history files.

To remove all generated checkpoints and histories from the current directory:

```bash
rm -f akarsh_ckpt_*.pt
rm -f *_history.csv
```

Then run the experiment again.

**Do not run the above command if you need to keep previous experiment results.**

# 38. Troubleshooting

## `ModuleNotFoundError`

Make sure the virtual environment is active and install the missing package:

```bash
source .venv/bin/activate
pip install <PACKAGE_NAME>
```

---

## CUDA is not available

Check:

```bash
python -c "import torch; print(torch.cuda.is_available())"
```

If it prints `False`, the script will use CPU. For full ViT experiments, a CUDA-enabled PyTorch environment and a compatible NVIDIA GPU are recommended.

---

## ViT weights are not downloading

Make sure the machine has internet access and run the experiment again:

```bash
python akarshprompt_boundedcode.py
```

---

## DataLoader / shared-memory error

Use zero workers:

```bash
AK_WORKERS=0 \
python akarshboundedmedical.py
```

The scripts already configure PyTorch multiprocessing to use the `file_system` sharing strategy.

---

## Experiment starts from an old checkpoint

Remove the corresponding checkpoint, or remove all generated checkpoints if you are certain they are no longer needed:

```bash
rm -f akarsh_ckpt_*.pt
```

# 39. Important Notes

- The default experiments can be computationally expensive because they use a ViT-B/16 backbone and multiple federated communication rounds.
- Use `AK_FAST=1` only for quick sanity checks.
- Use the full configuration for final thesis experiments.
- Keep the configuration fixed when comparing different prompt-pool policies.
- The generated `data/`, checkpoint (`*.pt`) and history (`*.csv`) files are experiment artifacts and do not need to be committed to GitHub unless specifically required.

---

# 40. Main Research Focus

The experiments are designed to study the behaviour of rehearsal-free prompt-based federated continual learning when moving from natural images to medical images.

The analysis focuses on:

- Medical-image classification performance
- Non-IID client effects
- Catastrophic forgetting
- Federated classifier drift
- Prompt-pool storage
- Communication and storage efficiency
